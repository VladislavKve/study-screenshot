## Что есть (разведка 03.11)
- Исходник: /home/mosi/Documents/studyPCcontrol/deploy/study-screenshot.sh (bash-установщик; внутри Python 3 + zenity + PIL + qrcode, обёртка на C с setgid studymark, расширение GNOME study-windowinfo@study.local). Только Ubuntu 26.04 GNOME Wayland.

- sig = HMAC-SHA256 (12 hex) ключом /etc/study/mark.key (на Citadel: studyPCcontrol/secrets/mark.key). Проверка: deploy/study-mark-verify.py; для ОП.09 — pkt-eval/stamp_check.py.
- Сохранение: ~/Изображения/Скриншоты/<Фамилии>_ПК<N>_<время>_<id>.png + буфер обмена.

## Предлагаемый план (координатор КС-54, уточни и реши стек сам)
1. Windows первой: один .exe без установки и без среды выполнения. Кандидат — Go (собирается на нашем сервере кросс-компиляцией, win32 API без cgo: снимок экрана/области, активное окно GetForegroundWindow, буфер обмена; чистый Go QR). Flutter/Kotlin тоже возможны, но Flutter для Windows собирается только на Windows, Kotlin требует Java — обоснуй выбор.
   Поток: значок в трее + горячая клавиша (Print в Windows занят — например Ctrl+Shift+S), окно «группа + фамилии (до 2) + работа», весь экран / область, плашка и QR как сейчас, сохранение в «Изображения\Скриншоты» и копия в буфер.
2. Формат QR — v5, совместимый по полям с v4 (os вместо iface где нужно); обновить study-mark-verify.py, чтобы проверял и v5.
3. ПОДПИСЬ — главный вопрос: на ПК студента секретный ключ не спрятать, HMAC можно подделать. Варианты для Влада: (а) без надёжной подписи — штамп и QR как сдерживание; (б) в момент снимка утилита отправляет хеш на наш сервер (маршрут на servermcp/Caddy), сервер возвращает подпись со своим временем — проверяемо, нужен интернет. Рекомендую (б), без сети — (а) с пометкой «не заверено».
4. Mac — вторым этапом: нужен Mac для сборки/проверки и разрешение «Запись экрана» в macOS.
5. Тест: на ПК преподавателя (Windows, onyx_pc_*, why по-русски), только после «да» Влада на запуск .exe на его ПК.
